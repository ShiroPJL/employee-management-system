# Task Template

> Use this structure for a specific unit of work. Small tasks may use only the sections they need.
>
> For the active task, keep the working copy aligned with Workflows/tasks/CURRENT.md. Do not copy permanent project rules into every task.

## Task ID / Name

-

## Status

Use a simple status such as Backlog, Current, Blocked, or Done.

-

## Objective

Describe what this task is intended to accomplish.

## Background / Problem

Record only the context needed to understand why the task exists.

## Relevant Files / Areas

List known files, modules, services, or repository areas. Leave unknown items unresolved until investigation.

-

## Requirements

Record confirmed task-specific requirements. Do not invent requirements.

-

## Constraints

Record restrictions specific to this task. Refer to Workflows/RULES.md for permanent project rules.

-

## Expected Behavior

Describe the observable intended result when relevant. Omit or leave unused when it does not apply.

## Verification / Testing

Record checks appropriate to the change. Verification should be proportional to the task.

-

## Completion Criteria

Describe the concise conditions that make this task complete.

-

## Notes / Progress

Record brief progress or findings when useful. Do not turn this into a session diary.
